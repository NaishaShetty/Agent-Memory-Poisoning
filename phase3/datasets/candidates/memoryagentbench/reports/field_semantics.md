# MemoryAgentBench -- Field Semantics Report

Grounded in: full-scan aggregate statistics (`reports/raw_inventory.md`) plus direct reads
of representative rows from each of the 22 distinct `source_task_name` values (LongMemEval
row 17 read in full for `haystack_sessions` structure; `entity2id.json` read in full).

## Top-level parquet columns (every split)

| Field | Meaning | Required/Nullable | Empty-string meaningful? | Agent-visible or evaluator-only | Stable across revisions? | ID or display label? | Source-grounded or benchmark-generated? |
|---|---|---|---|---|---|---|---|
| `context` | The full injectable text corpus for this row -- what gets chunked and fed to the agent incrementally per the benchmark's "inject once, query multiple times" protocol. | Required, non-null in all 146 rows (full scan). | N/A -- never empty in this dataset. | Agent-visible (this IS the memory content). | UNKNOWN whether byte-identical across HF revisions before the one used here -- the HF README's changelog documents structural changes (uuid->qa_pair_ids rename, sample removals) but does not state whether `context` text itself was ever edited; not independently verifiable without diffing prior revisions, which was out of scope for this candidate pass. | Not an ID -- raw content. | Source-grounded (comes from underlying corpora: RULER/Wikipedia-derived text, novels for DetectiveQA/InfBench, dialogue transcripts for ICL/Recsys/LongMemEval, synthetic fact lists for FactConsolidation/EventQA). |
| `questions` | List of question strings, one per QA pair, all posed against the same shared `context`. | Required; non-null, non-empty-string in all 3671 QA pairs scanned. | N/A -- never empty in this dataset. | Agent-visible. | Same caveat as `context` -- not independently diffed across revisions. | Not an ID. | Mixed: some source-grounded (e.g. RULER/LongMemEval questions reused from those benchmarks), some benchmark-generated (EventQA/FactConsolidation questions authored by the MemoryAgentBench team per the paper). |
| `answers` | List of lists: `answers[i]` is the set of acceptable answer-alias strings for `questions[i]` (e.g. `["10th and 11th centuries", "in the 10th and 11th centuries", ...]`). | Required; non-null, non-empty list, no null/empty member strings in the full scan. | N/A. | **Evaluator-only** (this is the gold answer set). | Same caveat as above. | Not an ID. | Mixed, same provenance split as `questions`. |
| `metadata.source` | The specific sub-dataset/task-variant name (e.g. `ruler_qa1_197K`, `factconsolidation_mh_6k`, `longmemeval_s*`). | Required; non-null in all 146 rows. | N/A. | Agent-visible in the sense that it identifies the task family (not gold-answer-bearing), but this candidate's normalization places it at the top level of both memory and task records rather than inside `agent_visible`/`evaluator_only`, since it is metadata ABOUT the task rather than task input or gold output. Not itself leakage-risk under `phase3/evaluation/contracts/boundary.py`'s FORBIDDEN_KEYS (it is not an answer/evidence/label field). | Stable naming convention observed across the dataset card's documented revisions (the changelog discusses ID-field renames and record removals, not source-name renames). | Display label / task-family identifier, not a unique record ID. | Benchmark-generated (assigned by the MemoryAgentBench authors to name each source task configuration). |

| `metadata.previous_events` | List of prior-event summary strings for EventQA rows only (temporal event chain context). | Nullable; non-null only on the 17 `eventqa_*` rows. | Not observed. | Agent-visible (part of the temporal-reasoning task setup). | Not diffed. | Not an ID. | Source-grounded, derived from the underlying novel's narrative. |
| `metadata.keypoints` | List of reference bullet points used to judge a produced summary's quality (Long_Range_Understanding rows only). | Nullable; non-null only on the 110 Long_Range_Understanding rows. | Not observed. | **Evaluator-only** (these are grading criteria for an LLM-judge, i.e. gold-adjacent, not agent input). | Documented as newly ADDED to the dataset on 2025-07-22 per the changelog (did not exist in the initial 2025-07-07 release) -- explicit documented instability. | Not an ID. | Benchmark-generated (authored to support LLM-judge scoring). |
| `metadata.haystack_sessions` | Nested list-of-lists-of-turns (`session -> turn -> {content, role, has_answer}`), LongMemEval rows only (5 of 146 rows). | Nullable; non-null only on those 5 rows. | Not observed empty. | **Evaluator-only for `has_answer`** (a boolean per turn marking where the gold evidence lives -- this is evidence-location ground truth and must never reach the agent). `content`/`role` are themselves agent-visible in the sense that they ARE the conversational content being memorized (functionally a more structured duplicate of what's also embedded as plain text in `context` for other task types) -- but because `has_answer` is interleaved at the same nesting level as a sibling key on each turn object, this candidate's normalization places the ENTIRE `haystack_sessions` structure under `evaluator_only` rather than trying to strip `has_answer` out turn-by-turn, to avoid any risk of a future integration accidentally exposing it. | `metadata.question_dates` | Per-question date string (e.g. `"2023/05/27 (Sat) 22:54"`), LongMemEval rows only. | Nullable; non-null only on 5 rows. | Not observed. | Evaluator-only (temporal metadata used for LongMemEval's time-sensitive question categories; not needed by the agent to answer, and could leak temporal-reasoning shortcuts if given directly alongside the gold answer path -- conservatively evaluator-only here, though a case could be made it's also legitimately part of question framing; this candidate does not assert which and marks it evaluator-only as the safer default). | Same instability note as above. | Not an ID -- a value. | Source-grounded (from original LongMemEval question metadata). |
| `metadata.question_ids` | Per-question ID distinct from `qa_pair_ids`, LongMemEval rows only (e.g. `"a4996e51"`). | Nullable; non-null only on 5 rows. | Not observed. | Evaluator-only-adjacent identifier (addressing key into the original LongMemEval benchmark, not gold content itself). | The HF README explicitly states: *"The `question_ids` is only used in Longmemeval task"* -- confirmed in the full scan (null on all 141 non-LongMemEval rows). | ID. | Source-grounded (carried over from the original LongMemEval dataset's own question IDs). |
| `metadata.question_types` | Per-question category string, LongMemEval rows only (e.g. `"multi-session"`, `"knowledge-update"`). | Nullable; non-null only on 5 rows. | Not observed. | Evaluator-only (a task-difficulty/category label, i.e. an evaluation annotation, not needed by the agent and matches the spirit of `boundary.py`'s `task_labels`/`evaluation_label` FORBIDDEN_KEYS). | Not diffed. | Display label. | Source-grounded (carried over from LongMemEval's own category taxonomy). |

## Auxiliary file: `entity2id.json`

31,161-entry flat JSON object mapping DBpedia resource URIs (e.g.
`<http://dbpedia.org/resource/Aaron_Russo>`) to integer IDs. Per the GitHub README:
*"Do not forget the entity2id.json for Movie Recommendation task"* -- this is almost
certainly the ID lookup table the `recsys_redial_full` task's numeric answer strings
(e.g. `"7008"`, `"4611"`) resolve against (movie entity IDs), though this candidate did
NOT independently verify that every recsys answer ID appears as a value in this map --
that would require a join this stage did not attempt (out of scope: no model
integration, no join/enrichment pass; flagged as a limitation in the README). Preserved
verbatim in `raw/hf_dataset/entity2id.json`; not restructured into `normalized/`.

## Fields NOT found anywhere in the dataset

Whole-dataset field-name scan (via `pandas` column/struct introspection across all 4
parquet files) found no `parent_ids`, `equivalent_to`, `conflicts_with`,
`superseded_by`, `evidence_memory_ids`, or any other explicit lineage/evidence-linkage
field at any granularity. This is a positive, structural confirmation of absence, not
an inference from missing documentation.
